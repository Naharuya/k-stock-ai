# 2.0 후보 조회 API

현재 API는 로컬 입력 파일을 분석하며 OpenDART 지분공시 자동 갱신을 선택적으로 사용할 수 있습니다. 실거래와 주문 기능은 계속 차단됩니다.

## 데이터 준비

기본 입력은 Git에서 제외되는 `data/v2-input.json`입니다. 다른 위치는 서버 환경변수 `KSTOCK_V2_INPUT_PATH`로 지정합니다. 기존 파일은 자동 생성하거나 덮어쓰지 않습니다.

입력은 `analysisDate`(ISO 날짜), `companies` 배열, `evidence` 배열이 필요합니다. 회사에는 `ticker`, `market`(`KR` 또는 `GLOBAL`), `companyName`을 지정합니다. 같은 시장·종목 중복은 허용하지 않습니다. 회사 최대 500개, 근거 최대 5,000개입니다.

근거 필수 항목은 `src/v2/contracts.js`의 계약을 따릅니다. `sourceUrl` 또는 `sourceName`이 있어야 하며 공개 관측일 `observedAt`이 D-2 필터를 통과해야 합니다. 필터의 날짜 경계는 한국 시간 기준입니다. 거래일과 공개 관측일을 혼동해서 입력하지 마세요. 점수는 검증된 투자 성과나 수익률을 의미하지 않습니다.

## OpenDART 자동 갱신

서버 환경에 `KSTOCK_V2_OWNERSHIP_ENABLED=true`, `KSTOCK_DART_ENABLED=true`와 기존 `OPENDART_API_KEY`를 설정하면 후보 조회 시 KR 회사의 지분공시를 갱신합니다. 기본값은 비활성화이며 이번 개발에서는 실제 키나 운영 설정을 변경하지 않았습니다. 회사의 `corpCode`가 없으면 기존 종목코드 매핑기를 사용합니다. KR은 최대 10종목이며 각 회사에 두 API를 순차 호출합니다. 같은 종목 목록은 10분 동안 메모리 캐시를 사용하고 동시 요청은 수집을 공유합니다. 수집 실패 시 503을 반환하며 오래된 캐시로 성공을 표시하지 않습니다.

대량보유와 임원·주요주주 소유보고의 보유 수량·증감을 근거로 변환합니다. 원문 보고자 이름은 저장/출력하지 않고 해시 식별자로 연결합니다. 해시는 익명성을 보장하지 않습니다. 원본 응답과 수집 결과를 디스크에 쓰지 않으며 입력 파일을 덮어쓰지 않습니다. 사용자 계정 정보나 토큰은 OpenDART에 보내지 않습니다. API 인증키와 조회 회사 코드만 전송합니다.

접수일은 보수적으로 해당 한국 날짜의 마지막 초를 공개 관측 시각으로 사용합니다. 실제 거래일은 알 수 없으므로 `transactionAt: null`입니다. 보유 증감이 곧 시장 매수·매도라는 뜻은 아닙니다. [대량보유 공식 계약](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS004&apiId=2019021)과 [임원·주요주주 공식 계약](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS004&apiId=2019022)을 따릅니다.

활성화 시 수동 KR 근거는 수집된 공시로 교체하고 GLOBAL 근거는 유지합니다. 회사의 재무·평가·위험 점수와 `analysisDate`는 입력 파일 기준으로 유지하므로 해당 값을 최신 기준으로 준비해야 합니다. 분석 기준일 이후의 공시는 D-2 필터에서 제외됩니다. 정기 예약 수집은 아직 남아 있습니다. 응답 `dataMode: OPENDART_OWNERSHIP`과 `collection`에서 수집 시각·건수를 확인할 수 있습니다.

## 버크셔 SEC 13F 연결

`KSTOCK_V2_SEC_ENABLED=true`와 `KSTOCK_SEC_USER_AGENT`를 서버 환경에 지정합니다. User-Agent는 앱 식별 정보와 실제 연락용 이메일을 포함해야 합니다. 예시 형식은 `K-Stock AI research <연락용 이메일>`입니다. API 키·가입·결제는 필요하지 않습니다. 이번 개발에서 운영 환경변수나 연락처를 설정하지 않았으며 실제 외부 호출 검증도 하지 않았습니다.

입력의 GLOBAL 회사에는 기존 필수 항목 외에 `cusip`(9자리), `securityClass`(원문 클래스와 일치), `cusipSource`(해당 매핑을 확인한 HTTPS 원문)를 넣습니다. 매핑 출처의 정확성은 운영 전에 확인해야 하며 코드가 URL 내용까지 검증하지는 않습니다. 종목명 유사도나 임의의 추측으로 티커를 연결하지 않습니다. 매핑은 최대 20개이며 동일 CUSIP·클래스 중복은 오류입니다. 사용자 입력 파일은 수정하지 않습니다.

후보 조회 시 버크셔 공시 목록 중 D-2 이전에 공개된 최신 공시를 선택합니다. 조회한 최근 8개 공시 안에 해당 공시가 없으면 실패합니다. 최신 적격 공시가 정정 공시이면 해당 버크셔 근거를 제외하고 대상 GLOBAL 회사에 검토 필요 상태를 부여합니다. 공시 기준 분기 말·공개 관측일·거래일(null)을 별도로 기록하며 전분기 증감·신규 매수·청산을 추정하지 않습니다. 원문 날짜에 시간이 없으므로 미국 동부 표준시의 해당 날짜 마지막 초를 관측 시각으로 사용합니다. 서머타임에는 실제보다 늦게 잡는 보수적 처리입니다.

일반 주식 수량(SH)만 연결하며 풋·콜 옵션과 미매핑 종목을 제외합니다. 같은 종목의 여러 공시 행은 보유 수량을 합산합니다. 모든 수동 GLOBAL 근거를 SEC 수집 근거로 교체하므로 다른 GLOBAL 근거를 유지하려면 SEC 갱신을 끄세요. KR 수집과 함께 활성화할 수 있습니다.

같은 분석 기준일·회사 설정은 10분 메모리 캐시를 사용합니다. 동시 요청은 수집을 공유하며 서비스의 SEC 호출 시작 간격은 프로세스 전체에서 최소 250ms입니다. 여러 프로세스를 운영할 경우 합산 호출 제한은 별도로 관리해야 합니다. 실패 시 503을 반환하고 오래된 수집 결과를 정상 결과로 표시하지 않습니다. 입력 파일·디스크에 수집 결과를 저장하지 않습니다. SEC에는 User-Agent 연락처와 조회 대상 정보가 전송되고 사용자 토큰은 전송하지 않습니다.

응답 `dataMode`는 SEC만 활성화 시 `SEC_13F`, 두 수집기 활성화 시 `OPENDART_AND_SEC`입니다. `secCollection`에 공시번호·분기 기준일·수집 시각·연결 근거 수·미매핑 행 수를 표시합니다. 화면의 종목 상세에서 분기 기준일도 확인할 수 있습니다. 다른 운용사, 전분기 비교, 정정 공시 병합, 실제 SEC 호출 검증은 남아 있습니다.

## SEC Form 4 내부자 거래

`KSTOCK_V2_FORM4_ENABLED=true`와 위의 `KSTOCK_SEC_USER_AGENT`를 설정합니다. GLOBAL 회사에 발행사 `cik`(숫자 문자열)와 `form4SecurityTitle`(원문 주식 종류와 정확히 일치하는 문자열)을 지정해야 합니다. XML의 발행사 CIK와 거래소 기호도 회사 설정과 일치해야 합니다. 기본 비활성화이며 실제 이메일·운영 환경은 이번 개발에서 변경하지 않았습니다.

최대 5개 발행사의 최근 제출 목록과 해당 분석 기간에 겹치는 추가 과거 제출 파일을 조회합니다. 분석 기준 시점 30일 전 날짜 이후 제출된 D-2 적격 Form 4를 사용합니다. 회사당 추가 파일은 최대 3개이며 한도를 넘으면 조회 불완전 오류로 중단합니다. 회사별 적격 공시 기본 한도는 5개이고 `KSTOCK_V2_FORM4_MAX_FILINGS`로 1~20개까지 지정할 수 있습니다. 해당 한도를 넘으면 임의로 잘라서 분석하지 않고 오류로 중단합니다. 구간에 4/A 정정 공시가 있으면 해당 회사의 Form 4 근거를 제외하고 검토 필요 상태를 부여합니다. 최근·과거 목록의 같은 공시번호는 중복 제거하며 내용이 다르면 오류입니다. 파일 이름은 지정 CIK의 submissions JSON 형식만 허용합니다.

`form4Collection.coverage: SUBMISSION_DATE_WINDOW`, `windowStart`, `historyFilesRead`로 수집 범위와 추가 파일 조회 수를 표시하며 웹에도 안내합니다. 전체 거래 생애 이력을 의미하지 않으며, 선택한 제출일 구간 외의 공시와 정정은 반영하지 않습니다. 과거 파일 목록은 [SEC 공식 submissions API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)의 파일·날짜 범위 메타데이터를 따릅니다.

비파생상품 거래의 P(시장 또는 사적 매수)·S(시장 또는 사적 매도)만 수량 증가·감소 근거로 사용합니다. 취득(A)/처분(D) 방향이 코드와 맞지 않으면 실패합니다. 보상·옵션 행사·증여·기타 코드, 파생상품, 설정한 주식 종류와 다른 거래는 제외됩니다. 신고 거래일은 `transactionAt`, 공개 관측일은 제출일 마지막 시각으로 분리하며 10b5-1 계획 거래 표시를 보존합니다. 가격·각주 해석은 자동 수행하지 않습니다. 여러 신고자는 CIK 집합으로 한 번만 연결하며 이름·주소·서명을 보관하거나 응답에 포함하지 않습니다. CIK는 공개 식별자이며 익명 데이터라는 뜻은 아닙니다.

버크셔 13F와 KR 근거를 유지하고 Form 4 근거를 추가합니다. 수동으로 입력한 기존 `sec:form4:` 근거는 새 수집 결과로 교체합니다. 활성화된 모든 수집기는 공통 SEC 호출 간격 제한을 사용하고 10분 캐시·동시 요청 공유를 적용합니다. 수집 실패는 503이며 부분 결과를 정상 완료로 표시하지 않습니다. 결과를 디스크에 쓰지 않습니다. Form 4 활성화 시 응답 `dataMode: SEC_FORM4_COMBINED`와 `form4Collection`이 추가되고 각 수집기의 메타데이터도 유지됩니다.

공식 의미는 [SEC Form 4 안내](https://www.sec.gov/files/form4.pdf)와 [내부자 거래 안내](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-69)를 참고하세요. 전체 이력·정정 병합·각주 및 거래 가격 해석·실서비스 호출 검증은 남아 있습니다.

## 조회

- `GET /api/v2/candidates`: 승인된 후보를 점수순으로 반환합니다. `KR` 최대 15개, `GLOBAL` 최대 20개이며 `evaluatedCount`는 전체 평가 회사 수입니다.
- `GET /api/v2/candidates/:ticker?market=KR`: 평가된 회사의 점수, 승인 여부, 위원회 판단, 에이전트별 위험·반대 논거, 통과한 원본 근거를 반환합니다. 제외된 회사도 이유 확인을 위해 상세 조회할 수 있습니다.

두 시장에 같은 종목 기호가 있으면 상세 조회에 `market`이 필수입니다. 시장 간 근거를 공유하지 않습니다. 외부 접속 모드에서는 기존 Bearer 인증을 동일하게 적용합니다. 응답은 `Cache-Control: no-store`를 사용합니다.

파일이 없으면 목록은 `status: NO_DATA`와 빈 배열을 반환합니다. 임의의 예시 후보를 넣지 않습니다. 파일이 잘못됐거나 안전 설정을 위반하면 503 `CANDIDATES_UNAVAILABLE`, 종목이 없으면 404, 잘못된 시장 또는 시장 구분이 필요한 요청은 400입니다. 파일 내용과 내부 오류는 API 오류에 노출하지 않습니다.

## 검증 범위

웹 홈의 **분석 후보** 메뉴에서 후보를 불러온 뒤 **근거와 위험 보기**를 선택합니다. 한국·글로벌 목록, 분석 기준일, 자료 시차, 종목 점수, 출처와 공개 관측일, 사실·해석, 위험과 반대 신호를 표시합니다. 데이터 없음과 조회 오류는 별도로 안내합니다. 기존 토큰 입력란을 공유하며 토큰은 탭 메모리에만 유지합니다. Android 네이티브 후보 화면은 아직 연결하지 않았습니다.

후보 API 핸들러는 네트워크 리스너 없이 검증합니다. 외부 접속과 실제 운영 서버 검증은 이번 개발 범위에서 생략했으며 통과로 기록하지 않습니다.

```bash
node --test test/v2_candidates.test.js test/v2_agents.test.js test/v2_scoring.test.js
```


## 정정 공시 검토 상태

정정 공시는 자동 병합하거나 무시하지 않습니다. 대상 회사는 다른 근거가 있어도 승인·순위에서 제외됩니다. API 목록의 `status: REVIEW_REQUIRED`와 `reviewCandidates`, 상세의 `candidate.reviewRequired`에 검토 사유·공시번호·공개 관측일·SEC 원문 링크를 제공합니다. 화면의 **정정 공시 검토 필요**에서 해당 종목을 확인할 수 있습니다. 이는 데이터 검토 상태이며 외부 계정 승인 요청이 아닙니다.

13F 정정은 현재 연결된 버크셔 대상 GLOBAL 회사에, Form 4 정정은 해당 발행사에 적용합니다. 수집기 캐시에 검토 상태도 함께 저장합니다. 네트워크·응답 오류와 조회 한도 초과는 계속 503이며, 정정 발견만으로 전체 서비스 오류를 반환하지 않습니다. 정정의 원본 지정·각주·수정 범위 검증과 자동 병합은 아직 구현하지 않았으므로 수동으로 해제하는 API도 제공하지 않습니다.

## 후보 분석 배치 실행

`node src/v2/run_candidates.js --check`는 입력을 분석하되 외부 수집기를 호출하지 않습니다. 환경의 수집 활성화 플래그와 무관하게 네트워크 갱신을 생략하고 요약만 출력합니다. 입력이 없거나 잘못됐으면 종료 코드 1입니다.

`node src/v2/run_candidates.js --collect`는 활성화된 수집기를 호출하고 실행 시각을 분석 기준일로 사용합니다. 최소 하나의 수집기가 활성화되어야 합니다. 회사 재무·위험·평가 입력은 자동 갱신하지 않으므로 운영자는 해당 입력의 최신성을 별도로 확인해야 합니다. 기본 출력은 Git에서 제외되는 `data/v2/latest.json`이며 `KSTOCK_V2_OUTPUT_PATH`로 변경할 수 있습니다. 입력 파일과 같은 출력 경로는 거부합니다. 파일 권한은 0600, 임시 파일을 쓴 뒤 원자적으로 교체하며 실패하면 기존 출력은 유지합니다. 이 경로는 실행 결과 한 개만 유지하며 과거 보고서를 자동 축적하지 않습니다.

기본 웹 조회는 기존 입력·수집 경로를 사용합니다. 아래의 배치 보고서 읽기 설정을 켜면 저장된 결과를 조회할 수 있습니다. OS 예약 작업 설치, 서버 배포, 실제 수집 실행은 이번 개발에서 하지 않았습니다. 배치 실행 경로를 먼저 준비했으며 예약 운영 전 실제 연락용 User-Agent·종목 설정·실서비스 검증이 필요합니다. 로그에는 후보 내용·토큰·이메일 대신 집계 수치만 출력하고 실패 원문은 기록하지 않습니다.

## 배치 보고서 웹 조회와 예약 미리보기

서버에서 `KSTOCK_V2_READ_BATCH_REPORT=true`를 지정하면 후보 API는 `KSTOCK_V2_OUTPUT_PATH`(기본 `data/v2/latest.json`)의 보고서를 읽으며 조회 요청으로 외부 수집기를 실행하지 않습니다. 배치 보고서의 버전·날짜·시장·점수·근거·승인 조건을 확인하고 후보 순위를 다시 구성합니다. 파일이 없으면 NO_DATA, 잘못된 파일은 503입니다. 최초 실행이나 설정 전환 시 기존 수집 결과를 입력 파일로 복사하지 마세요.

생성 시각 또는 분석 기준 시각이 36시간을 넘으면 `status: STALE`로 표시하고 KR/GLOBAL 순위를 비웁니다. 상세는 과거 참고용으로 남지만 `approved`는 false이며 화면에 과거 보고서임을 안내합니다. 이는 보고서의 최신성 검사이며 개별 재무 입력이 최신이라는 보장은 아닙니다. 미래 시각이 현재보다 5분 이상이면 오류입니다. `schemaVersion: 1`인 새 배치 출력만 받으므로 기존 출력은 배치를 다시 실행해 갱신해야 합니다.

사용 가능한 명령:

- `npm run test:offline`: Android 외부 네트워크·외부 접속 테스트를 제외한 내부 회귀 검사. 제외된 테스트를 통과로 표시하지 않습니다.
- `npm run v2:check`: 외부 수집 없이 입력 검증.
- `npm run v2:collect`: 설정된 수집기 실행·최신 보고서 생성.
- `npm run v2:schedule:preview`: Mac LaunchAgent XML 출력. 설치하거나 실행하지 않습니다.

예약 미리보기는 매일 기기 로컬 시간 06:30이며 한국 시간 운영 시 macOS 시간대가 Asia/Seoul이어야 합니다. `RunAtLoad`와 `KeepAlive`는 꺼져 있습니다. 토큰·이메일·API 키나 수집 활성화 플래그를 plist에 넣지 않고 프로젝트의 .env를 배치 실행 시 읽습니다. 설치 전에 `data/v2` 로그 폴더와 올바른 실제 수집 설정이 준비되어야 합니다. 예약을 활성화하거나 운영 서버를 변경하는 작업은 아직 하지 않았습니다. 기본 로그는 원문·개인정보를 포함하지 않는 요약과 일반 오류이며 로그 순환은 미구현입니다.

## SEC 연간 재무 연결

`KSTOCK_V2_FINANCIALS_ENABLED=true`이면 GLOBAL 회사(CIK 필수, 최대 5개)의 SEC companyfacts를 조회합니다. 기존 연락용 User-Agent와 공통 호출 간격 제한을 사용합니다. Apple 설정에 이 옵션을 추가했으며 기존 오전 06:30 배치에서도 함께 실행됩니다. 추가 개인정보·유료 API·주문 기능은 없습니다.

미국 us-gaap의 USD 연간 10-K 항목만 사용하고 공개일에 D-2 필터를 적용합니다. 회계기간 종료일만으로 공개 여부를 판단하지 않습니다. 매출의 연간 기간(300~400일)을 기준으로 같은 공시번호·기간에 속한 순이익·영업현금흐름·설비 투자·자산·총부채·자본을 선택합니다. 같은 기간 값이 충돌하면 실패합니다. 전년 매출은 직전 연간 기간만 비교하고 ROE는 양수인 기초·기말 평균 자본으로 계산합니다. 자료가 없거나 자본이 0 이하이면 해당 비율을 만들지 않습니다. 연간 기준일이 550일을 넘으면 불완전 자료로 처리합니다. 잉여현금흐름은 영업현금흐름에서 설비 투자를 뺀 값입니다.

현재 연간 수치는 TTM이나 최신 분기 수치가 아닙니다. 현행 companyfacts에 남아 있는 정보만 사용하므로 과거에 공개됐다가 삭제된 사실까지 복원하는 완전한 시점별 데이터베이스는 아닙니다. 10-K/A는 자동 처리하지 않습니다. 기업별 비표준 태그는 지원하지 않습니다. ROE는 자사주 매입 등으로 자본이 줄 때 높아질 수 있습니다.

재무 참고 점수는 매출 성장·FCF 마진·ROE·자본/자산 비율의 고정 규칙으로 계산하며 실적 예측이나 수익률 검증 점수가 아닙니다. 매출 성장 점수는 (성장률%+10)×2.5, FCF 마진·ROE는 30%를 100점으로 변환, 재무 구조는 (자산-총부채)/자산×100을 사용하고 각 점수를 0~100으로 제한합니다. 가중치는 25:25:20:20입니다. SEC 수치만으로 경쟁우위(moat)는 추정하지 않습니다.

재무 입력이 부족하거나 가치평가 입력이 없으면 `dataBlockers`를 표시하고 후보 승인을 막습니다. 전체 보고서의 `status: DATA_INCOMPLETE`, 목록의 `incompleteCandidates`, 상세 `financialSnapshot`으로 상태와 연간 재무를 확인합니다. 가격·시가총액·동종기업 비교를 수집하지 않았으므로 SEC 재무를 연결한 회사의 수동 가치평가 점수는 지우고 `VALUATION_DATA_MISSING`으로 남깁니다. 실제 Apple 재무 수집과 배치 보고서 읽기는 확인했지만 주가 기반 가치평가·분기/TTM·정정 재무 병합은 아직 남아 있습니다.

## 미국 종가 수집 경로

Alpha Vantage `TIME_SERIES_DAILY`의 compact 응답을 읽는 수집기를 추가했습니다. `KSTOCK_V2_US_PRICE_ENABLED=true`와 비공개 .env의 `ALPHAVANTAGE_API_KEY`가 필요합니다. 로컬 비공개 키를 설정하여 Apple 수집을 활성화했습니다. [공식 가격 API 계약](https://www.alphavantage.co/documentation/#daily)과 [무료 키 발급 안내](https://www.alphavantage.co/support/#api-key)를 참고하세요. 공식 무료 서비스는 하루 25회 범위이며 Apple 한 종목의 일일 배치에는 가격·분할 이력 조회 총 2회가 추가됩니다. 공개 배포·상업적 사용은 제공자 이용 조건을 별도로 확인해야 합니다. 현재는 개인용 로컬 리서치 범위입니다.

수집기는 최대 5종목을 순차 조회하며 자동 재시도하지 않습니다. API 키는 서버 요청에만 사용하고 원문 URL·응답 오류 메시지를 로그나 보고서에 기록하지 않습니다. 키 미설정·제공자 제한·응답 오류는 실패로 처리합니다. User-Agent의 SEC 연락처나 사용자 토큰을 가격 제공자에게 보내지 않습니다. 동일 분석일·종목은 프로세스 내 6시간 캐시를 공유합니다. 다중 프로세스·재시작에 걸친 일일 호출량 제한은 구현하지 않았으므로 활성화 시 정해진 일일 배치로 사용하세요.

실시간 가격 대신 D-2 이전에 공개된 최근 일별 종가를 선택합니다. 미국 동부 표준시 해당 날짜 마지막 시각을 보수적 공개 시각으로 사용하며 7일 이상 오래된 가격은 STALE입니다. 다른 종목 응답·0 이하 가격·유효하지 않은 날짜는 후보 가격으로 사용하지 않습니다. compact 범위를 벗어난 오래된 분석일은 가격이 없다는 오류를 반환합니다.

가격은 분할·배당 미조정 종가입니다. SEC의 같은 연간 공시에서 희석 EPS를 읽어 양수인 경우에만 종가/EPS를 참고 배수로 계산합니다. 이 값은 TTM PER이 아니며 `SPLITS` 이력을 조회하여 연간 실적 종료일 이후부터 가격 기준일까지의 분할을 확인합니다. 해당 구간에 분할이 있거나 응답·기준일이 유효하지 않으면 배수 계산을 보류합니다. 분할 이력이 없는 경우에도 비교평가 자료가 없어 가치평가 점수는 생성하지 않습니다. 제공자 이력에 의존하는 검사이며 EPS를 임의로 조정하지 않습니다. 가격 연결만으로 기존 가치평가 부족 차단을 해제하지 않습니다. API 상세의 `priceSnapshot`·`corporateActionSnapshot`·`valuationSnapshot`과 웹 상세에서 날짜·금액·제약을 확인할 수 있습니다.


### 가격 제공자 호출 관리

가격·분할 응답을 비공개 `data/v2/alpha-vantage-state.json`에 저장하여 프로세스 재시작과 분석 기준일 변경 시에도 6시간 동안 재사용합니다. 조회 시마다 D-2 가격 선택과 재무 기준일 검사를 다시 적용합니다. 정상 검증을 통과한 응답만 저장하며 API 키·연락처·제공자 오류 원문은 저장하지 않습니다. 파일은 0600 권한으로 원자적으로 교체하며 Git 제외 대상입니다.

이 프로젝트의 최근 24시간 호출을 최대 20회로 제한합니다. 실패한 호출도 사전 예약하여 집계하고, 제공자 제한/안내/오류 응답 또는 HTTP 429는 6시간 재호출 보류 상태로 저장합니다. 무료 서비스의 하루 25회 기준보다 보수적인 로컬 제한이며 다른 앱에서 같은 키를 사용하는 횟수는 알 수 없습니다. 이 기능 도입 전 호출은 집계에 포함되지 않습니다. 만료된 응답과 24시간 이전 호출 기록은 다음 접근 때 제거합니다. 로컬 상태 파일 삭제는 호출 집계도 초기화하므로 제한 우회 목적으로 삭제하면 안 됩니다.

여러 프로세스가 동시에 수집하면 상태 파일 잠금을 먼저 얻은 프로세스만 진행하며 다른 프로세스는 `PRICE_COLLECTION_BUSY`로 종료합니다. 프로세스 강제 종료로 잠금 파일이 남으면 수집을 차단합니다. 모든 수집 프로세스가 종료된 것을 확인한 뒤 관리자가 잔여 잠금을 제거해야 합니다. 손상된 상태 파일은 새 집계로 덮어쓰지 않고 `PRICE_STATE_INVALID`로 차단합니다. API 오류 발생 시 기존 후보 보고서는 보존하며 기존 36시간 신선도 검사가 적용됩니다.

검증된 양수 연간 EPS와 가격, 분할 확인 결과가 준비된 경우 `annualEarningsYieldPct`(연간 EPS/종가×100)를 참고값으로 제공합니다. 이 값은 배당률·예상 수익률·TTM 지표가 아니며 가치평가 점수에 사용하지 않습니다. 과거 배수 분포와 동종기업 비교, FCF 수익률 데이터 연결은 아직 남아 있습니다.


### 로컬 비교 자료 계약

GLOBAL 회사에 선택적으로 `sector`와 `valuationComparables: { history: [], peers: [] }`를 넣을 수 있습니다. 각 배열은 최대 100개입니다. 각 관측값에는 `ticker`, `market: "GLOBAL"`, `currency: "USD"`, `basis: "ANNUAL_DILUTED_EPS"`, 양수 숫자 `close`·`dilutedEps`, `priceDate`·`financialPeriodEnd`(YYYY-MM-DD), `publishedAt`(실적 공개 시각), `splitReviewed: true`, `priceSourceUrl`·`financialSourceUrl`이 필요합니다. 출처는 인증정보·쿼리·fragment 없는 HTTPS URL만 허용합니다. 비교기업에는 회사와 같은 `sector`도 필요합니다. 임의 수치는 실제 입력 파일에 넣지 않습니다.

공개 시각은 가격일 종료 시각 이전이어야 하며 공개·가격 시각에 D-2 기준을 적용합니다. 실적 종료일부터 가격일까지 550일을 넘는 자료는 제외합니다. 과거 표본은 동일 종목의 현재 가격일 이전 자료만 받고 최근 6년 범위에서 연도별 최대 1개를 사용합니다. 최소 3개 연도와 700일 이상의 표본 간격이 필요합니다. 비교기업은 동일 시장·통화·업종·가격일의 서로 다른 회사 최소 3개가 필요하며 자기 자신은 제외합니다. 이 선택 규칙은 통계적 대표성이나 공정가치를 보장하지 않습니다.

API의 `valuationComparisonSnapshot`에는 표본별 종가/연간 EPS, 중앙값, 현재 배수의 중앙값 대비 차이(%), 부족한 자료와 제외 사유를 제공합니다. `REFERENCE_READY`는 형식·범위 조건 충족만 의미합니다. 입력의 경제적 동질성과 원문 일치 여부, 분할 검토 선언은 독립적으로 검증하지 않습니다. 따라서 `rankingEligible: false`이며 가치평가 점수나 후보 승인 조건을 해제하지 않습니다. 실제 과거 가격·당시 공개된 실적·비교기업 수집은 아직 연결하지 않았습니다. 기존 Apple 입력과 저장된 보고서는 이번 작업에서 변경하지 않았습니다.
