# 새벽 연구·아침 보고 운영

로컬 K-Stock의 기존 30분 Scheduler 마지막 단계에서 실행한다. 별도 타이머, OS 작업, 외부 알림 전송을 만들지 않는다.

- 시간대: Asia/Seoul.
- 새벽 확인: 02:00 이상 06:00 미만, 기존 주기의 실제 실행만 기록한다.
- 아침 보고: 07:30 이후 첫 완료 주기에 하루 한 번 저장한다. 수집/검증 소요시간과 기존 주기 기준점에 따라 늦어질 수 있다.
- 자료 수집은 기존 활성·승인된 공식 경로와 호출 상한/기업별 캐시/공급자 대기를 그대로 따른다. 새벽이라고 같은 자료를 강제로 다시 수집하지 않는다.
- Mac이 깨어 있고 서버가 실행 중이어야 한다. 절전 해제/예약 깨우기/로그인 자동 시작은 구성하지 않았다. 서버 미실행 시간을 소급 실행했다고 기록하지 않는다.

홈의 Mac mini 연구 상태에서 날짜별 마지막 아침 보고를 펼친다. 실제 생성 시각, 관측된 새벽 슬롯, 현재 후보/추천 통과 수, 기업별 보류 사유가 표시된다. 첫 보고는 신규 후보 증가 비교 기준이 없으므로 증가 수를 null로 보존한다. 자료를 읽지 못하면 실패 보고를 저장하며 당일 보고를 조용히 성공으로 덮어쓰지 않는다. 실패 보고의 자동 재생성은 당일 수행하지 않는다.

API: 기존 GET `/api/v2/research/dashboard`의 `overnight`. 저장: `data/v2/research-automation/overnight.json`. 파일 잠금과 재시작 후 슬롯·일별 중복 방지를 적용한다. 최근 보고 최대31개/새벽 기록 최대248개를 저장한다. 개인정보/연락처/비밀값은 보고서에 포함하지 않는다.

현재 서버가 종료된 뒤 같은 로컬 모드로 실행할 때 사용할 명령:

```sh
KSTOCK_PEER_WORKER_ENABLED=true KSTOCK_V2_READ_BATCH_REPORT=true KSTOCK_EXTERNAL_ACCESS_ENABLED=false KSTOCK_BROKER_ENABLED=false KSTOCK_LIVE_TRADING_ENABLED=false node src/server.js
```

이미 서버가 실행 중일 때 두 번째 서버를 실행하지 않는다. 원천 수집 승인 여부는 기존 설정을 따른다. 자동 코드 개발/JINI 개발 HOLD 해제, 운영 배포, 추천 활성화, 실제 주문 기능과 별개다. 보고서의 검증 통과 수는 전략 예측력이 입증됐다는 의미가 아니다.
