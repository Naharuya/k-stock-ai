# ARI 공통 법적·사회적·개인정보 개발 기준

적용 범위: 현재 ARI 프로젝트와 앞으로 생성되는 모든 앱/웹/서버/관리자/에이전트.

## 1. 기본 원칙
- 코드가 실제로 하지 않는 일을 개인정보처리방침·약관·스토어 문구에서 한다고 표현하지 않는다.
- 법적/사회적/개인정보 위험은 출시 직전에 문서만 고치는 문제가 아니라 기획 → 데이터 흐름 → 구현 → 테스트 → 스토어 고지까지 연결해 관리한다.
- 자동으로 해결 가능한 코드·문서·테스트 문제는 에이전트가 먼저 해결한다. 로그인·본인인증·결제·외부 계정 설정·법적 사실값·물리적 조치만 사용자 승인/직접 조치 Gate로 남긴다.
- 내부 일정이나 검토 목표는 외부 공개 약속·법적 고지·실제 데이터 이전 시점으로 표현하지 않는다.

## 2. 개인정보 필수 Gate
- 수집 최소화: 기능에 필요하지 않은 개인정보는 받지 않는다.
- 처리 목적: 수집 항목마다 목적을 명확히 연결한다.
- 보유기간: 정책에 정한 기간이 실제 DB/파일/로그/백업 파기 로직과 일치해야 한다.
- 삭제권: 계정/개인정보를 수집하는 서비스는 안전한 본인확인 기반 삭제/탈퇴 경로를 제공하고 테스트한다.
- 로컬 데이터: 기기 저장 정보의 삭제 방법, 백업 여부, 암호화 필요성을 검토한다.
- 로그/관리자: 원문·비밀값·민감정보를 불필요하게 기록/노출하지 않는다. 관리자 화면은 최소정보만 표시한다.
- 전송 보안: 운영 개인정보 전송은 HTTPS/TLS를 사용한다.
- 국외이전: 실제로 해외 사업자/리전에 개인정보가 전달되는 시점과 대상이 확정되기 전에는 추측해 고지하지 않는다. 도입 확정 시 실제 시작 전에 정책·동의·스토어 고지를 갱신한다.
- OS/기기 제공자 처리: 음성인식, 푸시, 로그인 등 운영체제/플랫폼이 별도 처리할 수 있는 데이터는 자사 서버 처리와 구분해 설명한다.
- 아동: 만 14세 미만 또는 아동 대상 가능성이 있는 앱은 법정대리인 동의·최소수집·보호자 권리·스토어 연령정책을 별도 검토한다.

## 3. AI·자동화
- AI 사용 여부와 사용 목적을 사용자에게 오해 없게 설명한다.
- 민감정보를 외부 AI에 전달하기 전 실제 제공자, 전달 항목, 목적, 보유조건을 확인한다.
- 위기·의료·심리·재무 등 고위험 영역에서 AI를 전문가나 공식 기관의 대체자로 표현하지 않는다.
- 생성형 AI 출력은 사실·권리·안전 검증 없이 자동 공개/집행하지 않는다.
- 유료 API·실거래·실결제·대량 외부 호출은 별도 승인 Gate를 유지한다.

## 4. 사회적 안전
- 차별·혐오·낙인·과도한 개인화·중독 유도·기만적 UX를 피한다.
- 실제 사용자 수, 효과, 성능, 전문가 검증, 제휴/공식성 등을 근거 없이 주장하지 않는다.
- 위기상황/응급상황은 현실의 도움을 우선 안내한다.
- 접근성, 작은 화면, 글자 확대, 키보드/스크린리더 등 기본 접근성을 검증한다.

## 5. 약관·스토어·마케팅
- 개인정보처리방침, 이용약관, Play Data Safety, Apple App Privacy, 앱 권한 설명은 실제 코드/운영 설정과 일치해야 한다.
- 계정 생성, 결제, 구독, 광고, 위치, 카메라, 마이크, NFC, 연락처 등 기능이 추가되면 관련 정책 Gate를 자동 추가한다.
- 건강·의료·금융·아동·종교·위치정보 등 민감 카테고리는 별도 정책 검토를 거친다.
- 마케팅 문구는 검증 가능한 사실만 사용하고 오해를 유발하는 효과 보장 표현을 피한다.

## 6. 저작권·콘텐츠
- 외부 텍스트·이미지·음원·데이터셋·경전/문헌·지도·아이콘은 라이선스와 출처를 확인한다.
- 출처가 불명확한 자료는 운영 콘텐츠에 자동 포함하지 않는다.
- 라이선스 의무와 오픈소스 고지는 배포물에 반영한다.

## 7. 보안·운영
- API key, password, token, keystore, private key를 Git/로그/클라이언트 코드에 노출하지 않는다.
- 운영 DB 삭제/초기화, 서명키 교체, production migration, 외부 계정 변경은 승인 Gate를 유지한다.
- 테스트 데이터와 실제 사용자 데이터를 분리한다.
- 개인정보/보안 관련 변경은 회귀 테스트와 secret scan을 함께 수행한다.

## 8. 출시 전 필수 확인
출시 후보는 아래 항목이 모두 실제 상태와 일치해야 한다.
1. 운영 주체/문의처
2. 수집 항목·목적
3. 실제 보유기간 및 파기 구현
4. 계정/데이터 삭제 경로
5. 국내/국외 데이터 흐름
6. 외부 SDK·AI·클라우드 제공자
7. 권한·연령·아동 정책
8. 약관·개인정보처리방침
9. Play Data Safety / Apple App Privacy
10. 저작권·라이선스
11. 보안/secret/로그
12. 실제 기기·운영 환경 검증

## 9. 프로젝트별 적용
각 프로젝트는 이 공통 기준을 최소선으로 사용하고, 프로젝트 특성상 더 엄격한 규칙이 있으면 그 규칙을 우선한다.

## 10. 새 프로젝트 규칙
새 ARI 프로젝트를 만들 때는 첫 커밋 단계에서 이 기준을 복사하거나 동등한 내용을 `docs/ARI_COMPLIANCE_STANDARD.md`에 생성하고, 루트 `AGENTS.md`에서 이를 필수 Preflight 문서로 참조한다.
