# Mac mini 백엔드 구현 및 결과 회수 지시서

작성: 2026-10-20 / 사용자 요청: 구체적인 구현 지시 전달 및 코드·테스트 결과 회수.

## 목표와 우선 작업

추천 보류 사유를 생성하는 `src/v2/research_readiness.js`의 입력 검증을 강화한다. 현재 가격·주식수는 `> 0`만 검사하므로 문자열 숫자와 Infinity가 PENDING으로 표시된다. 이를 실제 유한한 양수 number만 인정하도록 수정한다. TTM 지표와 기존 추천 게이트의 의미는 유지한다.

1. AGENTS.md, docs/ARI_COMPLIANCE_STANDARD.md, 본 지시서, 대상 코드와 테스트를 읽고 Git 경로·remote·branch·HEAD·기존 변경을 기록한다.
2. 가격 close와 shares count가 문자열, Infinity, -Infinity, NaN, 0, 음수, null, 누락이면 INSUFFICIENT_DATA로 분류한다. 유효한 유한 양수는 PENDING을 유지하며 VERIFIED로 승격하지 않는다.
3. 위 비정상 관측값의 evidence.observedValue는 null로 정규화한다. 유한 양수인 실제 관측값은 보존한다. 입력 객체를 변경하지 않는다.
4. `test/research_readiness.test.js`에 경계값 회귀 테스트를 추가한다. 기존 정상 관측·URL·기간·HOLD 동작을 보존한다. 잘못된 입력이 검증된 자료처럼 표시되지 않는지 확인한다.
5. 허용 task `kstock-offline-test`를 실제 실행한다. 마지막 제품 코드 수정 이후 실행한 결과만 최종 결과로 보고한다. `git-diff`로 실제 변경을 확인한다. 실패는 원인을 수정하고 다시 실행하거나 FAIL/BLOCKED로 남긴다.

## 제출물과 회수 기준

- 보고서에 작업 시작/종료 UTC 시각, 실제 작업 경로·브랜치·기준 HEAD, 변경 파일과 변경 이유를 기록한다.
- 실제 테스트 명령, 실행 결과 PASS/FAIL/NOT RUN, 총수·실패수·종료 코드와 실행 영수증 경로를 기록한다. 실행기 task 이름을 실제 셸 명령과 구분한다.
- diff 또는 실제 변경 파일을 제출하고 git-diff 결과로 변경을 입증한다. 설명만 작성하고 구현 완료로 보고하지 않는다.
- 도구가 테스트를 막으면 실제 오류와 필요한 실행 경로를 남긴다. 테스트 결과를 추정하거나 이전 결과를 재사용하지 않는다.
- 회수 담당 Codex는 실행 응답·job 영수증, 코드 diff, 테스트 로그를 확인한다. 필요한 경우 독립 재실행 후에만 검증 완료로 처리한다.
