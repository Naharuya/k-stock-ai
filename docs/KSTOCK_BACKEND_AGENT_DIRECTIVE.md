## 실행 순서

1. 실제 코드·런타임·작업 큐·호출 정책을 확인하고 기준 상태를 기록한다. 인수인계 679 회귀 PASS / Android 계약 3 PASS는 재실행 전 현재 결과라고 보고하지 않는다.
2. 기존 30분 재검증의 잠금, 변경 감지, 캐시, 호출 제한, 제한된 백오프와 재시작 복구를 조사한다. 동일 원천을 신규 사건으로 세지 않는다. 부팅 서비스 변경 필요 시 제안만 기록한다.
3. Apple 외 공식 사건 하나를 우선 끝까지 검증한다. 기존 승인·활성화된 SEC, OpenDART, KIS, 공식 IR/중앙은행 읽기 경로만 사용한다. 실행 도구가 수집을 지원하지 않으면 공식 조회를 수행했다고 주장하지 않고 차단 사유와 필요한 실행 경로를 기록한다.
4. 공식 발언, 실제 거래, 보유 변화, 투자 의향, 기업 자사주 집행, AI 추론을 구분한다. 13F 거래일은 확인되지 않으면 null. acceptedAt과 publicAvailableAt을 동일시하지 않는다. 정확한 공개 시점과 CONSERVATIVE_START를 구분한다.
5. 가격 유형·기업행동·배당·시간대·공통 거래일을 검증하고 1·5·20거래일 가격수익률 및 동일 기간 초과수익을 각각 계산한다. 결측 보간, 가짜 가격, 미확인 조정계수 금지. 보수적 연구를 실체결 성과로 표현하지 않는다.
6. 발언자-행동 주체 관계, 기업 관련성, 시간 순서와 방향 근거를 충족한 경우에만 결합 신호를 판정한다. 반대 근거와 손실 사례도 보존한다. 기존 Apple 2건 및 Microsoft 음의 초과수익 사례를 보존한다.
7. 국내 금융 큐는 독립 유지한다: SK 자기주식 1,014주, DB 정정 차이 9건, 비교기업 6개 배수별 표본 부족. 기준일·주식 종류·수량·효력일·공개 시점을 검증한 근거만 반영한다. KRX LOGOUT은 AUTH_BLOCKED, 우회/무한 재시도 금지. PBR 조건과 표본 최소 기준을 완화하지 않는다.
8. 기존 API를 호환 유지한다. 상태, 통화·단위·기준일·출처·차단 사유를 제공한다. API 계약 변경은 별도 제안하며 프론트엔드를 직접 수정하지 않는다.
9. 변경에 맞는 오프라인 fixture 검증 및 가능한 기존 회귀를 실행한다. 외부 조회는 테스트와 분리해 출처·시각·호출 수를 기록한다. 실행하지 못한 테스트는 NOT RUN. 테스트 수만으로 실제 자료 확보나 예측력을 주장하지 않는다.
