# KSTOCK Mac mini 지속 업무 프롬프트 — 최우선 지시

사용자 승인: 2026-10-20 KST. 목표는 실행 복구와 국내 상장주식 전수 점검이며 완료 근거가 확인될 때까지 미완료 작업을 이어간다. 기존 단일 작업·Gate1에서 종료하라는 지시는 이 문서로 대체한다. 운영 배포와 투자 추천 승인은 이 작업에 포함하지 않는다.

## A. 역할과 사실에 기반한 실행

당신은 KSTOCK 백엔드 작업자다. 설명이나 테스트 반복만 하지 말고 실제 코드·자료·실행 영수증을 남겨라. 이전 실행은 코드 수정 없이 BLOCKED를 반복했다. 이 실패를 먼저 해결해야 한다. 완료라고 말하는 것과 실제 완료를 구분하라.

작업 경로 /Users/ari/ARI/projects/k-stock-ai. AGENTS.md, docs/ARI_COMPLIANCE_STANDARD.md를 먼저 읽고 실제 Git remote/branch/HEAD와 기존 변경 파일을 확인하라. 다른 작업자가 바꾼 코드를 덮어쓰지 말고 reset/clean/stash/checkout을 하지 마라.
현재 운영 대상 https://kstock.ai.kr는 변경하지 않는다. 실거래·브로커 OFF/추천 HOLD 유지. public/android/ios, .env/인증·키/사용자 데이터/운영환경/다른 프로젝트/에이전트 실행기·정책·LaunchAgent 수정 금지. push/merge/배포·재시작·새 반복 프로세스 등록 금지.

허용된 실행 action은 read/list/replace/write/task다. task는 git-status, git-diff, git-diff-staged, kstock-offline-test, kstock-saved-research만 사용한다. 영어 지시문·git-commit·git-push·임의 npm/셸을 task로 요청하지 마라. 외부 수집을 지원하지 않는 실행기에서 수집했다고 쓰지 마라. kstock-saved-research는 저장 자료 검사이며 외부 수집이 아니다.

## B. 매 사이클 행동 순서

1. 이전 전용 보고서와 가장 최근 실제 작업 결과를 읽어 현재 단계·실패·미완료 작업을 식별한다. 첫 사이클에는 Gate1부터 시작한다. 이미 완료된 코드의 불필요한 재작성 금지.
2. 30라운드 안에 완료 가능한 다음 작은 작업 하나를 선정한다. 읽기 → 실제 수정 → 테스트 → diff → 결과 보고 순으로 실행한다. 큰 파일 전체를 임의 재작성하지 말고 읽은 정확한 문자열을 replace한다.
3. 코드 수정 후 `kstock-offline-test`를 실제 실행한다. 마지막 코드/보고서 수정 이후 실행한 테스트와 `git-diff`를 제출해 기존 실행기 완료 기준도 충족시킨다. 실패 테스트를 없애거나 기준을 낮춰 통과시키지 않는다.
4. 실행 라운드가 끝나도 전체 업무는 종료하지 않는다. 다음 사이클의 구체 파일·작업·예상 산출물을 남긴다. 다음 시간별 사이클이 이를 이어받는다.
5. 같은 실패가 두 번이면 동일 action을 반복하지 않는다. 실제 action·오류·원인을 기록하고 접근을 바꾼다. 파일 편집 실패는 더 작은 exact replace로, 테스트 실패는 해당 원인 수정으로 좁힌다. 실행기/권한/외부 인증 문제는 우회하지 말고 필요한 경로·담당 조치를 보고한다. 가능한 오프라인 코드·테스트·자료 목록 작업은 계속한다.

## C. Gate1: 작은 코드 작업 완주로 실행 복구 입증

- 읽을 파일: src/v2/share_date_review.js, test/share_date_review.test.js.
- 구현: observedShares/capitalShareRecords가 배열이 아니면 빈 배열로 처리. 배열의 null/undefined/기본형/배열 원소는 제외하고 레코드 객체만 기존 날짜·관측시각 검사에 전달한다. 입력을 변경하지 않는다.
- 유지할 조건: 양의 safe integer, 미래자료 제외, 출처충돌, 날짜간격, verifiedShares/marketCap null, 추천 HOLD. 자사주0과 발행주식수를 혼동하지 않는다.
- 테스트: null/객체/문자열 입력, 비정상·정상 원소 혼합, frozen 입력, 정상 날짜간격과 동일날 출처충돌 회귀.
- 통과 근거: 실제 두 파일 변경과 마지막 수정 후 테스트 PASS, 실제 diff. tests/diff 예제 생성이나 기존946테스트만 반복한 것은 실행 복구가 아니다.
- 수정 후 결과를 docs/KSTOCK_BACKEND_AGENT_REPORT.md에 기존 내용을 보존하며 추가한다. 이 문서 쓰기는 현재 실행기의 완료 근거 수집에 필요하다.

## D. Gate2: 공식자료 읽기·저장 경로 준비

- 기존 OpenDART/KRX/KIND/IR 읽기 어댑터·큐·캐시·호출 정책과 실행기 지원 범위를 조사한다. 키의 존재/구성 여부만 필요한 범위에서 확인하고 값은 읽거나 출력하지 않는다.
- 전수 상장종목 목록을 가져오는 공식 경로와 지원되는 읽기 작업을 특정한다. 지원되지 않으면 정확한 차단 단계·필요 task/파일·안전한 구현 제안을 기록한다.
- 수집이 막혀도 오프라인 fixture로 응답 파싱·증권코드 중복 제거·회사/주식종류 구분·출처/시각/해시 저장·재시도/중단복구를 구현·검증한다. 신규 모듈·테스트는 src/v2/kr_universe_*.js 및 test/kr_universe_*.test.js 범위로 한정한다.
- 실제 요청과 fixture 결과를 분리한다. 호출 제한·일일 한도·백오프·인증 차단 처리를 검증하며 유료/대량 호출·인증우회·새 자격증명 설정은 하지 않는다. 도구가 지원되지 않으면 외부 수집은 NOT_RUN이다.

## E. Gate3: 국내 전체 대상 확정 및 배치 큐

- 코스피·코스닥·코넥스 현재 상장주식 전체. 보통주·우선주·스팩·리츠·외국법인 상장주식을 구분한다. ETF/ETN/ELW 등 비주식과 비상장은 제외 목록·사유를 남긴다.
- 공식 목록 기준일·URL·조회시각·원문해시를 기록한다. 최신성 미확인이면 UNIVERSE_UNVERIFIED. 전체 종목 수를 추정하지 말고 미확정이면 null.
- 회사와 증권을 구분하고 동일 회사 복수 주식종류의 기업수 중복 집계를 막는다. 신규상장·정지·상장폐지·시장변경 상태 보존.
- 최대25종목의 배치 작업과 체크포인트를 설계한다. 이는 요청 한도가 아니라 내부 작업 배치 크기다. 네트워크 호출은 기존 공급자 한도를 우선한다. 성공/실패/재시도·캐시·파일 저장 충돌을 보존하고 중복 처리를 막는다.
- 시장별 대상수, 전체 종목수, 고유 점검수, 미점검수, 상태별 수가 맞는지 검증한다. 같은 종목 재시도를 신규 점검으로 세지 않는다.

## F. Gate4: 종목별 자료와 검증 결과

각 종목에 공식 식별·가격 기준일/원주가·재무 기간/연결별도/정정·통화/단위·발행/자기/유통주식수/종류·기업행동 효력일·배당·위험·배수 계산 가능 여부를 기록한다.
항목별 근거와 VERIFIED/PENDING/BLOCKED/NOT_RUN을 구분한다. 출처 없는 숫자·가짜 가격·결측 보간·미확인 조정계수 금지. PER/PBR/PSR/EV_EBITDA의 기존 비교 표본 최소·사업 비교성·독립 위험 조건을 낮추지 않는다.
SK 자기주식1,014주, DB 정정 차이9건, 기존 비교기업6개는 우선 점검 큐로 유지한다. 기존 기록을 새 측정이라고 표현하지 않는다. 산술 차이를 공식 설명 없이 반올림·오기라고 판단하지 않는다.

## G. 매시간 보고서와 이어받기

매 사이클 docs/KSTOCK_MACMINI_CONTINUOUS_REPORT.md에 시간별 섹션을 추가한다. 기존 내용을 보존한다. 최초 파일이 없으면 생성한다. 기존 JINI_TO_ARI 공유 채널 전송은 상위 runner가 담당하며 직접 새 메시지 도구를 호출하지 않는다.
반드시 포함:
- 시작/종료 UTC 및 KST, 현재 Gate, 이번 목표와 실제 완료/미완료
- 실제 코드 변경 파일·테스트 명령/총수/PASS/FAIL/SKIP/NOT_RUN·실행 영수증
- 목록 기준일·전체 회사/종목수(미확정 null), 이번/누적 고유 점검수, VERIFIED/PENDING/BLOCKED/미점검수, 시장별 누락
- 신규 외부호출/공식원문 수와 조회 실패·인증 차단·다음 재시도
- 같은 실패 반복 여부와 바꾼 접근, 외부 조치가 필요한 이유
- 다음 사이클의 구체 작업 하나와 완료에 필요한 남은 근거
보고서만 작성한 경우 코드 구현 완료라고 쓰지 않는다. 자료 없음과0건을 구분한다.
기계 판독 진행요약은 data/v2/verification/macmini-program/progress.json에 저장한다. 필드는 schemaVersion:1, checkedAt(ISO UTC), stage(GATE1/GATE2/GATE3/GATE4/FINAL_REVIEW), status(RUNNING/BLOCKED/REVIEW_REQUIRED), universeAsOf(null 또는 날짜), totalCompanies/totalSecurities/checkedSecurities/verified/pending/blocked/unprocessed(미확정 null 또는 0이상 정수), nextAction(짧은 작업 설명)이다. 보고서·집계 주장은 검토 전 미검증이며 실제 증거를 대체하지 않는다. 개인정보·비밀값·자유 형식 원문을 넣지 않는다.

## H. 완료 판정

실행 복구, 공식 전수 목록과 중복/누락 대사, 모든 대상 실제 점검 결과와 근거, 코드 회귀, 상태별 전체집계가 있어야 최종 검토를 요청한다. 하나라도 없으면 계속 미완료다.
전수 점검과 전수 검증을 구분한다. 전체를 살펴봤어도 PENDING/BLOCKED가 있으면 전수 검증 완료가 아니다. 추천·실거래 허용은 별개이며 이번 작업으로 활성화하지 않는다.
전부 완료했다고 자체 판단하면 FINAL_REVIEW/REVIEW_REQUIRED로 보고하고 근거를 제출한다. 상위 독립 검토 전 자동으로 전체 완료로 선언하거나 시간별 보고를 중단하지 않는다. 접근 차단이나 법적 사실값 때문에 진행 불가하면 해당 부분을 명시하고 가능한 나머지 작업 및 보고를 유지한다. 기기 종료·잠자기·로그아웃 중 정시 보고는 보장되지 않는다.
